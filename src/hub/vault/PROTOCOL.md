# Memory Protocol

## Read protocol

1. Read `MEMORY.md` and `INDEX.md`.
2. Read the current project's overview and state.
3. Read recent sessions only if they are relevant.

## Write protocol

1. Append a session entry for substantive work.
2. Update the project's state.
3. Add stable facts only.
4. Update the indexes when you create a file.

## Quality rules

- Prefer facts the user stated or that you verified.
- Use `Recorded`, `Updated` and `Source` fields.
- Label uncertain items `unconfirmed`.
- Replace stale state instead of stacking it. Keep history in `decisions.md` or `archive/`.

## Privacy rules

- Never store secrets: passwords, keys, tokens, recovery codes, cookies, private keys, full account numbers.
- Store sensitive personal information only when it is needed for the work.

## Conflict rule

When a new fact contradicts the vault, ask the user, then update the vault.
